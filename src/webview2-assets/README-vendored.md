# Vendored web assets

Files served to the Markdown preview's WebView2 pane over a virtual host
(see [`specs/markdown-preview-pane.md`](../../specs/markdown-preview-pane.md)).

Unlike `src/md4c/` and `src/webview2/`, nothing here is compiled. These are
runtime assets copied next to the executable by the build and mapped into the
preview page as `https://notepad4.invalid/`.

## Files

| File | Purpose |
|---|---|
| `mermaid.min.js` | Renders ```` ```mermaid ```` fenced blocks as diagrams |
| `LICENSE.txt` | Mermaid's MIT license |

## mermaid.min.js

- **Upstream**: https://github.com/mermaid-js/mermaid
- **Version**: 11.12.0
- **Source**: `https://cdn.jsdelivr.net/npm/mermaid@11.12.0/dist/mermaid.min.js`
- **SHA-256**: `07e37dfa97b337ccc85365d57eddf99b9706f09db3b59b260d0333b23b343c4b`
- **License**: MIT (see `LICENSE.txt`)

This is the IIFE/classic build, not the ESM one. Its final statement is
`globalThis["mermaid"] = ...`, so a plain `<script src>` tag is enough and no
module loader is needed. If a future version drops that global assignment, the
preview will silently stop rendering diagrams — check the tail of the file
first when updating.

## Why bundled rather than loaded from a CDN

The preview would otherwise make a network request every time a Markdown file
is opened, fail entirely offline, and disclose editing activity to a third
party. Bundling costs ~2.7 MB in the repository and buys determinism: the
diagram renderer is pinned and reviewable.

## Updating

Download the pinned URL with a new version number, update the version and hash
above, and confirm the `globalThis["mermaid"]` assignment is still present:

```bash
tail -c 200 mermaid.min.js
```

Do not edit this file locally. Notepad4-specific behavior belongs in
`src/MarkdownPreview.cpp`, which owns the initialization script.
